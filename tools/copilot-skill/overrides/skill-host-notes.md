## Host notes

This skill runs with no hooks installed, so these guarantees rest on these instructions alone:

- **Tool roles**: this skill names tools by role, never by a host's tool name. Before Phase 1, resolve each role once to one concrete tool of this host and use that tool wherever the role is named: the **file-read tool** (read a file), the **file-write tool** (create a file with given content), the **file-edit tool** (replace part of an existing file), the **search tools** (text search over file contents, and file lookup by name pattern), the **shell tool** (run a POSIX shell command; every command this skill names is POSIX), the **URL-fetch tool** (fetch a URL over HTTP; this skill never requires it, HTTP goes through the shell tool, and the role is named only where the roles are forbidden to use it), the **subagent tool** (run a prompt as a separate general-purpose subagent, the host's default agent type, and return its result) and the **ask-user tool** (put a question to the user and return the answer within the same run; ending the turn to ask in prose does not count). A role this host has no tool for: the subagent tool → the degraded branch of Mandatory role invocations; the ask-user tool → the non-interactive fallbacks; any other role except the URL-fetch tool → `ERROR: this host offers no <role>` and stop.
- **PII and secrets**: never write an absolute home path (a path that begins with the user's home directory) into any generated file, spawn prompt, ticket or summary. Two exceptions: `{scratch}` (Argument Parsing) may be absolute (it lies under the system temporary directory, which may itself lie under the home directory when `TMPDIR` points there) and appears inside spawn prompts and in the Final summary's "saved at" and `Scratch:` lines; a `brief=` / `findings=` path is the user's own input and is echoed exactly as the user typed it in error lines and the Final summary. Neither is ever written into a ticket or sent to a destination. Pass the rubric as `{rubric_path}` (Pre-computed Context: `{skill_root}` as found, repository-relative or `~`-prefixed), never expanded. The same holds for secrets: the value of the variable an `api:` destination's `auth_env=` names, and any other token, never appears in a prompt, ticket, summary, error line or file; a shell command refers to it only as `$VAR` (see `references/destinations.md`).
- **Shell commands**: this skill declares no `allowed-tools`, so every shell command (`date`, `mktemp`, `ls`, `mkdir`, `mv`, `printf`, `git`, `curl`, `jq`, and `python3` for a workbook source) goes through the host's own permission prompt. Approve only the commands the steps above name. Every user-supplied path, directory, sheet name and identifier passes the character rule of Argument Parsing (no double quote, backtick, dollar, backslash or control character) before it reaches a double-quoted shell argument, so a name in any script is accepted and none can break out of its quotes.
- **File access and approvals**: the file-read and file-write tools must be able to reach the system temporary directory (`{scratch}`) in every mode, so allow it when the host limits file access to the repository. With `confirm=yes`, the `api:` adapter's shell commands (`jq`, `curl`) still go through the host's permission prompts unless the host pre-approves them.
- **Sources are read-only**: Intake (`source=`) reads files, one MCP tool result and one HTTP body each, writes only under `{scratch}/sources/`, and never calls a tool whose description says it creates, updates, deletes, sends or posts; an `mcp:` source is refused when its tool reads as anything but retrieval. The caps (60,000 characters per source, 150,000 in total, 8,000 of excerpts per planner spawn) bound every spawn prompt; raise nothing without checking the host's context window.
- **Python 3 for `.xlsx` sources only**: a workbook is read by `scripts/xlsx_to_text.py` (standard library only, run as `python3 -I`); every other source kind needs no interpreter. Without Python 3 on the PATH an `.xlsx` source is an `ERROR`, nothing else changes.
- **Remote creates are not transactional**: an `mcp:` or `api:` destination cannot roll back, so a failure part-way leaves the items already created in place; the run prints their identifiers and stops (Step DL-4).
- **Evaluator independence**: the ticket-evaluator is hermetic by instruction only. A general-purpose subagent carries every tool; its prompt (`references/agents/ticket-evaluator.md`) forbids reading any file other than the ticket inlined in that prompt, and the orchestrator inlines both the ticket and the rubric so the evaluator never needs to.
