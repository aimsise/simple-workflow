## Intake

Runs only when the request carried at least one `source=<spec>` token, right after the destination preflight and the creation of `{scratch}` (Argument Parsing) and before Phase 1, in every mode. Every rule, pattern, cap and `ERROR:` line is in [references/sources.md](references/sources.md); this section is the sequence.

1. **I-1 Enumerate.** Number the resolved source specs (every comma-separated spec of a `source=` token, each with its stated or inferred kind; `references/sources.md` `## Writing a source`) `S1`, `S2`, ... in request order; a `dir:` source expands into one id per supported file, in sorted name order, at its position. Check every spec against its pattern before anything is read, then create `{scratch}/sources/` with the shell tool running `mkdir -p`.
2. **I-2 Read each source, read-only.** `file:` with the file-read tool (`.xlsx` through the shell tool running `{skill_root}/scripts/xlsx_to_text.py`, the workbook read as a workbook); `dir:` as a list of `file:` sources; `mcp:` by one call of a tool whose description reads as retrieval; `api:` by one `GET` through the shell tool (`source_auth_env=` for the bearer token, never its value). A source that cannot be read → its `ERROR:` line, stop; nothing has been delivered.
3. **I-3 Normalize and cap.** Write `{scratch}/sources/S<n>.md` (header block + content) for each source, truncating one source at 60,000 characters with a `[truncated: ...]` line and `Truncated: yes`; when the files together exceed 150,000 characters → `ERROR: sources exceed the intake limit ...`, stop. Print one `WARNING:` line per truncated source and per `dir:` skip.
4. **I-4 Build the dossier.** Write `{scratch}/sources/dossier.md`: the index table (id, kind, origin, chars, truncated) and every normalized file verbatim.
5. **I-5 Derive what the request did not carry.** When the request text holds no description (only tokens), set `{intent}` to the line `Create tickets from the supplied sources: <origin of S1>[, <origin of S2>, ...]` and use it wherever a step names the bare description; derive `{parent-slug}` from the first source's name (a `file:` or `dir:` basename without extension, an `mcp:` source's `<server>-<tool>`, an `api:` URL's last non-empty path segment, else its host) with the kebab-case rule of Step D-1 and its `work-{yyyymmddthhmmssz}` fallback. With `brief=` or `findings=` nothing is derived here.
6. **I-6 Forward.** The researcher spawn gets the index table and the dossier path; the Phase 2 shrinkage scan covers the dossier; the decomposer spawn gets the dossier verbatim under `## Source dossier` (Form A and Form B) and, in Form B, the header `Dossier role: candidate` (bare or derived description) or `Dossier role: context` (brief); each planner spawn gets only the excerpts its ticket's `source_refs` name, under `## Source excerpts`; the ticket-evaluator gets nothing from the dossier. The decomposer's `**Partition basis**:` line is kept for the Final summary.

With `brief=` or `findings=` the dossier is context only and the partition basis stays with the brief or the findings units. With a bare description or none, the decomposer decides whether one source (or one part of it) is the partition basis, by the property stated in [references/spec-decomposer-input.md](references/spec-decomposer-input.md): two or more discrete items that each state their own scope and outcome as work still to be done. Intake writes nothing outside `{scratch}/sources/` and calls nothing that creates, updates, deletes, sends or posts.
